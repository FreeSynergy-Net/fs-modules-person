- M3, the lists (read only): `catalog/forms.json` declares `rows@1.0.0` (type `Profile`, scope `all`: `items`, `label` = display name, `preview` = first picture (`media`), `columns` = organizations, titles, emails, phones, nicknames with ONE value each (the one with the lowest `pref`, else the first), `state` = `me` | `account` | `contact`) and `single-record@1.2.0` (scope = the id of the profile, `urn:uuid:` or bare: `item`, `label`, `preview`, `state`, `fields` = the field table without `uid`, `prodId` and the picture, plus `describes`; a field with several items is the same path repeated, never joined). No command channel, no `open`/`actions`: nothing writes a profile. A test reads `schema/forms.txt` through the reader of fs-interfaces and fails where the catalog maps a channel the form does not have, leaves a required one out, exceeds a count or puts a field of the wrong type on a channel (the status `planned` of the forms there does not matter to the reader). `PersonCore` now holds ONE `PersonRepo` (new port: `MeRepo` + `ProfileRepo`; `PersonStore` is its adapter, one fs-objects store behind both, because `TursoStore` cannot be cloned; `StoreMe` and `StoreProfiles` stay and share the free steps). The list takes the cards of kind `group`, `org`, `location` and `device` out (`application` stays; the card stays readable by its id) and filter and paging are ONE step (`list_page`: a page holds `limit` listed profiles, the cursor is a place in the whole store, `total` counts the listed ones). Before any read the core asks the rules once whether this context may read at all, so a bot or another person makes no store read and sees no total (an unknown id looks like a known one); under allow-everything rules it reads, as the counter-proof shows. New sample provider (`SampleRepo`, `fs-person-service --sample`): ten fixed cards (the names and addresses of `fs_person_directory::sample`, RFC 9553 examples, one group, one organisation, one place, one device, an AI account), no clock, no randomness, the same on every run; `hello` says `fake` so a host never shows it as real; the same `PersonRules` stand before it, so it is no way round the rights. Pattern lines on every new type; files at most 300 lines. Written with the help of Claude (Anthropic).
